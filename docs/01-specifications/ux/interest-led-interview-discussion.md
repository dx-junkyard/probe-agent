## 1. 目的と境界

ユーザーは整理内容を読み、関心のあることを自由に質問して理解を深める。会話の途中で
得られた説明・経験・訂正をAIが構造化し、人が確認した内容を各インタビューへ補足する。
質問の前に分類、対象項目、回答フォームを選ばせない。説明を聞くだけで終えても成立する。

会話の起点は一つのInterview、反映先は候補ごとに一つ以上のInterview・項目である。
起点と反映先を分離する。会話履歴を他のthreadへ移動・複製・自動結合しない。
Systemの正準理解への昇格、既存の質問回答・Intent確認、調査実行はそれぞれ明示操作とする。

## 2. 代表シナリオ

検討用の架空例: Interview Aには「管理者向けの業務支援」と整理されている。

1. ユーザー: 「この目的って、現場の人にも関係する？」
2. AI: 保存済みの説明を根拠とともに答える。記録から判断できない利用実態を区別する。
3. ユーザー: 「実際は現場担当者が毎日使っていて、管理者は月末だけ確認する」
4. AI: まず発言に応じて対話を続ける。会話の横に「整理候補 1件」を控えめに表示する。
5. ユーザーが「ここまでを整理」を開く。AIは対象ユーザーの補足と未確認の利用頻度を分け、
   Interview Aの意図項目と、関連するInterview Bの運用説明への関連候補を提示する。
6. ユーザーは関連先と文言を確認し、Aへの補足だけを保存する。B向けは保留できる。
7. Aには元の会話への参照付きで補足が残る。既存回答や要約の更新は別の差分レビューで行う。
   BやSystem正準headは変わらない。

「毎日使うのでは？」という質問や「仮に毎日使うなら」という仮定は、この例の事実発言と
同じ候補にしない。AIの説明に対する相づちだけでも確定扱いにしない。

## 3. 画面と操作

| ID | 場面 | 表示・操作 |
| --- | --- | --- |
| IID-UX-01 | 会話開始 | Interviewに「この内容について話す」。右下の既存Botからも同じセッションthreadへ入る。項目の「AIと検討」は質問文と参照を補う任意の入口 |
| IID-UX-02 | 対話 | 主領域は会話。起点Interview名、参照している版、短い回答、根拠、必要な場合の聞き返しを表示。追加質問への回答を補足レビューで遮らない |
| IID-UX-03 | 関連を発見 | 「関連しそうなインタビュー」と理由を折りたたんで表示。AI提案と人が選んだ関連を区別。関連の採用だけでは本文を更新しない |
| IID-UX-04 | 整理 | 常時「ここまでを整理」。AIが候補を見つけてもモーダルを自動で開かない。候補0件なら「今回は内容の更新はありません」と表示し、変更を捏造しない |
| IID-UX-05 | レビュー | 「補足・訂正」「未解決の問い」「仮説」を分ける。各候補に原発言、AIによる整理文、関連先、変更理由を表示。全件未選択で開始 |
| IID-UX-06 | 保存 | 候補ごとに編集・保留・却下・関連先変更。「選択した補足を保存」は選択先への補足記録だけを作る。質問回答・要約更新・確定まで済んだと表示しない |
| IID-UX-07 | 既存内容の更新 | 保存済み補足から「既存の内容へ反映」を開き、更新先別に現在値と更新後を確認する。回答・Intent確認・候補版作成など実際の効果をボタンに明記 |
| IID-UX-08 | 戻る・再開 | Interview側に補足件数と起点会話へのリンク。会話側に保存先と結果へのリンク。再読込で保存結果・保留候補を復元する |

広い画面では整理内容と会話を並べて読む。補足候補は会話の補助領域にまとめる。
390pxでは「内容／会話／整理候補」を切り替え、入力中の文章・スクロール位置を保持する。
会話を開いている間に別Interviewを見ても送信先を黙って切り替えず、起点名と「このInterviewの
会話へ切り替える」を表示する。切替は別threadを開く操作であり、下書きを持ち越さない。
送信中のturnは開始時の起点・参照を固定し、応答を元threadへ配送する。

すべての操作にキーボードで到達でき、保存結果はaria-liveで通知する。色だけで状態を示さない。
音声も同じturn・保存境界を使う。録音中は候補生成の通知で遮らず、レビューは文字で確認できる。
無操作時間や音声の相づちを承認の代わりにしない。

## 4. 整理の意味

| 分類 | 意味 | 保存後の扱い |
| --- | --- | --- |
| 補足 | ユーザーが述べた追加情報 | 人が確認した補足記録。客観的に検証済みとの意味は持たない |
| 訂正 | 既存内容と異なるユーザーの説明 | 元の内容を残して記録し、差分反映を提案 |
| 未解決の問い | 会話で答えが出ていない点 | 未解決のまま保存。Q&Aをansweredにしない |
| 仮説 | AIまたはユーザーの暫定的な説明 | 暫定ラベルを維持。調査への昇格は既存JUの要件を満たす場合に別操作 |

AIが文言を要約しても、原発言へ戻れる。引用の主体と、整理文の著者と、保存を判断した人を
分ける。ユーザーが原発言にない内容をレビューで追加した場合は人の追記として記録する。
同じ論点の追記では以前の候補を勝手に消さず、差し替え候補として示す。

## 5. 例外と状態

| 状況 | 体験・次の操作 |
| --- | --- |
| 関連先を特定できない | 起点の未分類候補に残す。自由な質問は続けられる。保存前に関連先を選ぶ |
| 複数の項目が同名 | 違いと所属Interviewを表示して選択を求める。名前一致だけで更新しない |
| 他Interviewとの食い違い | 両方の説明、版、発言者を併記。AIが片方を正しいと確定しない |
| 整理中に新しい発言 | 「発言Nまでを整理」と表示。追加分を整理してもレビュー中の候補は上書きしない |
| 保存済み補足と重複 | 元の記録へのリンクを示す。文言が似ているだけでは自動統合しない |
| 参照版・更新先が変化 | 変更内容を示して再レビュー。保存済み補足は残り、要約反映は止める |
| premiseが古い | 歴史的文脈での会話・補足記録は維持。現在の正準との違いを明示し、既存rebase/branch導線へ案内 |
| LLMが使えない | 説明・整理を完了したと見せない。送信済み発言を保持し再試行を提示。人は手入力で補足を作れる |
| 保存結果が不明 | 保存要求IDで結果を確認。未確認のまま成功扱いにせず、同一要求を再送できる |
| 閉じたInterview | 関連参照は可能。補足保存・反映には既存の明示再開、または別Interviewの選択が必要 |

Interview WorkflowのW状態は既存エンジンが所有する。このUXは会話・補足レビューの状態を
別に持ち、補足件数だけでW状態や質問の回答済み件数を変更しない。

## 6. 受入条件

下位設計のIID-D/API/T契約と合わせて検証する。以下は未実測の受入基準である。

| ID | シナリオ | 合格条件 |
| --- | --- | --- |
| IID-AC-01 | 自由質問を3往復して終了 | 項目選択・保存を強制せず、起点threadで再開可能。domain更新0件 |
| IID-AC-02 | 具体的な経験を補足 | 根拠turnを提示し、選択したInterviewにだけ補足を保存。元会話へ戻れる |
| IID-AC-03 | 質問・仮定・AI推測・相づち | 事実や回答済み状態へ自動変換されない |
| IID-AC-04 | Aでの会話からBも関連 | 会話はAに残る。Bには承認した補足と参照だけが追加され、Bの会話履歴に混入しない |
| IID-AC-05 | 訂正から要約更新 | 差分を確認して候補revisionを作る。正準headは別の明示昇格まで不変 |
| IID-AC-06 | 対象変更・競合・削除・別System | 不正な更新0件。何を再選択・再レビューすべきかが分かる |
| IID-AC-07 | 再送・二重クリック・再読込 | 補足・domain更新の重複0件。保存済みと未保存を復元できる |
| IID-AC-08 | 画面移動中の遅延応答 | 起点threadにのみ回答が届き、新しい画面の候補・入力を上書きしない |
| IID-AC-09 | 390px・キーボード | 質問→候補編集→保存→起点に戻るを完走。主操作の隠れ・フォーカス喪失なし |
| IID-AC-10 | 内容理解の評価 | 代表利用者が根拠を説明でき、補足保存／要約反映／正準昇格の違いを説明できる |

利用者評価はシステムに不慣れな人3名と業務を知る人3名を最低構成とし、上記架空例と、
矛盾・未解決の問いを含む課題を用いる。質問完了率、関連先修正率、保存段階の誤認、
操作完了時間を実測する。重大な保存段階の誤認0件をリリース条件とし、未測定を0件にしない。

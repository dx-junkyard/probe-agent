# 目的・UX・機能の共同検討 Mock

新規UXの引き継ぎ用、単独HTMLの操作モックです。[正本の設計](../../01-specifications/ux/decision-discussion-workflow.md)を参照してください。`index.html` を通常のブラウザーで開きます。ビルド、依存追加、サーバー起動は不要です。

すべて架空fixtureです。本番の画面・ルート・API・DBを追加していません。外部通信、実LLM呼び出し、localStorage、ファイルへの保存は行いません。リロード／初期化で状態が消えます。これは提案されたUXの確認物で、既存機能の実装完了を示しません。

例題は「チームの作業計画」で、変更の影響を判断するため関連作業の理由表示を検討します。設計文書の例題とは別の架空fixtureです。

## 操作するシナリオ

1. 選択済みのGapから左のVision・Objective・Milestone・Journey・Requirement・Feature・Solutionと根拠をたどる。
2. 事実・解釈・仮説を読み分ける。機能不足候補、関係未登録、証拠不足／取得失敗、取得上限による省略を確認する。「省略した2件を確認」で追加取得を模擬する。
3. 「仮説を整理する」から競合説明・反証条件・次の調査を編集する。必須項目が空なら昇格を拒否する。
4. 人の操作で共同調査へ渡す。模擬結果では事実と暫定結果を分離し、未解決の比較調査を残す。
5. 元の議論で修正案を比較し、取り込む本文・受入条件を選択する。未保存の本文と競合する場合、保持／提案で置換を選択するまで反映できない。
6. フォームに反映した後で編集し、別操作の「保存（模擬）」を押す。Gapは未解決のまま、調査も未完了のまま。
7. 「Gapの検討へ戻る」で同じGap・議論・共同調査の文脈に戻る。REQ-8 rev 6の模擬保存参照を表示し、「保存した文案を確認する」で保存文案を再表示できる。初期化とは異なり、仮説の編集内容と根拠の取得状態を保持する。

シナリオ選択で以下を確認できます。選択変更時には状態をリセットします。

| シナリオ | 表示と操作 |
| --- | --- |
| 通常 | 5段階を通して操作できる |
| 前提更新 | revision差分を表示し、古い前提での進行を停止。模擬再取得でGap rev 8に更新し、比較をやり直す |
| 取得失敗 | 機能の有無を未判定とし進行を停止。「取得を再試行する」でEV-12取得成功を模擬し、確認を再開する |
| 未対応 | 修正案の確認まで進めるが、フォーム反映を無効化。既存フォームでの手動編集を次の操作として示す |

## 実装者への引き継ぎ

- `fixtures` と画面遷移は全て `index.html` 内にあります。状態はメモリー上だけです。
- 本番では対象adapterと正本のrevision、取得範囲・省略件数・失敗理由をサーバーの契約から取得します。このMockの判定を本番のclient側ルールに移植しないでください。
- 仮説昇格、結果還流、提案生成、選択反映、保存は別操作です。判断項目の解決・採用・達成・優先度をフォーム反映対象に含めません。
- AC-1は受入条件の安定キーを表すfixtureです。nested itemのunknown key拒否・並び替え・revision競合・冪等性などの本番保証はこのMockでは実装していません。
- 前提更新・取得失敗の再取得は成功fixtureへの切り替えです。実行中・再取得失敗・同時編集・再試行による二重適用防止などは本実装側の受入試験が必要です。
- 共同調査の実行画面、任意の対象切替、仮説の却下、複数提案・複数セッションの管理はこのMockの対象外です。

## 確認記録

2026-09-06: インラインJavaScript構文、HTMLのID重複、根拠リンクの参照先、外部リソース／通信／永続化APIの不使用を静的確認。

既存 `apps/dashboard/node_modules/jsdom` を使ったDOM操作検証を実施し、以下が通過しました：追加取得、必須反証条件の空欄拒否、暫定結果、項目未選択の拒否、未保存競合の保持／置換、フォーム反映と保存の分離、保存後のGapへの帰還と文案の再表示・再編集、前提再取得後のrev 8継承、取得失敗の再試行成功、未対応時の反映停止、リセット、Mock常設表示。

主担当が許可された127.0.0.1限定HTTPプレビューで初期描画と正常系の実操作（仮説 → 調査 → 提案 → 競合保持 → フォーム反映 → 模擬保存 → 元Gapへの帰還）を確認しました。キーボードのみの完走・読み上げ・390px/1280pxのレスポンシブ描画は未検証です。詳細は ../../03-validation/decision-discussion-handoff.md を参照してください。

引き継ぎ時には上記4シナリオ、空欄の拒否、競合の保持／置換、項目未選択の拒否、保存後の再編集、リセットを実操作で確認してください。幅390pxと1280pxで横スクロール・重なりがないこと、およびTab／Enter／Spaceで操作できフォーカスと読み上げ通知が追えることも確認対象です。

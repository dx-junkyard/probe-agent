# LR-001: 境界と版を追う

**版:** 1。**状態:** candidate。**作成:** 2026-09-19。
[改善サイクル](../README.md) · [課題辞書](../../../02-challenges-and-decisions/issue-knowledge/dictionary.md)

適用条件: 生成・保存・適用をまたぐ契約、対象、依存版がある変更。
非適用条件: 文言だけの変更、利用価値の実測そのもの。競合を再現できない環境では競合保証を主張しない。

1. 目的・不変条件と対象版を固定し、起点から保存まで情報・条件・対象・版を表にする。
2. 正常・欠落・不正値・古い版・別System・再実行を使い、境界で何が失われるか再現する。
3. 契約の共有、値の伝達、状態の分離、判定の位置変更を比較し、最小の原因修正を選ぶ。
4. 正本と実装を更新する。データ変更時は移行・復旧を含める。
5. rootを変えず依存版だけ変更する、推論待ち中に別操作を行う、再配送する等、原因に合う反例で検証する。
6. レビューで前段・後段の片方だけが直っていないか確認し、失敗を是正する。
7. 結果様式へ効果・未観測・費用・見逃しを記し、IKとこのRecipeの適用条件へ返す。

停止条件: System混在、前提の暗黙上書き、予算超過が見えた時点で適用を止める。
証拠: 比較した版・入力、前後の状態、拒否時の無変更、再現コマンド。

見逃しへの注意: 事前の一回だけの判定、rootだけの比較、正常系だけのテストは競合を覆わない。

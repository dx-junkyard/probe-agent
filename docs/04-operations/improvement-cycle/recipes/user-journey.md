# LR-002: 起点から保存・復帰まで歩く

**版:** 1。**状態:** candidate。**作成:** 2026-09-19。
[改善サイクル](../README.md) · [課題辞書](../../../02-challenges-and-decisions/issue-knowledge/dictionary.md)

適用条件: 複数画面・フォーム・会話をまたぐ変更、保存済みと確定済みを区別するUX。
非適用条件: SDK関数の性能比較だけを目的とする変更。操作自動化だけで実利用者の理解を推定しない。

1. 利用者の目的と開始状態を定め、起点から復帰までの期待を利用者の言葉で書く。
2. 未表示フォーム、未保存、保存失敗、遅延応答、System切替、狭幅の条件で経路を歩く。
3. 到達不能・誤認・情報欠落を課題化し、導線・契約・状態表示を変える案を比較する。
4. 対象とACK、反映・保存・確定の境界を明示して修正する。
5. 実APIと画面で受入条件を確認。mock/実LLMを分け、reload後の復帰や二重適用も原因に応じて確認する。
6. 実利用者による確認が必要なら、対象者・課題・環境を定めて測る。未実測は保留して担当と再開条件を残す。
7. 是正後に結果と費用を残し、見逃し・非適用条件をこのRecipeへ追記する。

停止条件: 保存成否が分からないまま再試行が必要になった、未保存内容が失われた、実施予算に到達した。
証拠: 操作順、開始・終了状態、APIの保存版、画面での表示、未確認の操作・支援技術。

#452/#459と実ブラウザ観察。単体テスト合格と実利用評価を分けた点を再利用する。

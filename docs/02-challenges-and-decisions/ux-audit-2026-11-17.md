## 結論

個々の画面は「サーバーが決めた状態を表示する」「取得失敗と 0 件を分ける」をよく守っている。問題は画面と画面の間にあり、根は 4 つある。

1. 入口で「次の一歩」が複数あり、互いに食い違う。
2. 初回導線に行き止まりがあり、未解析を「問題なし」と表示する箇所がある。
3. 製品の中心である連鎖が、画面だけでは最後までつながらない(API はあるが入力面がない)。
4. 「確認・確定・承認」が多種類あり、何が変わるのかを読み取れない。

バックログは 54 件(P1: 19 件、P2: 32 件、P3: 3 件)。

## 製品の目的(監査の基準)

probe-agent は、既存ソフトウェアを「目的 → 利用者価値 → 設計 → 実装 → 実行時の現実 → 判断履歴」がつながった、検証・改訂し続けられるシステム像として扱うための基盤である。正本は [Vision・UX・コア機能要件](../00-product/vision-and-core-requirements.md)。

- **利用者:** 既存システムを理解し、変更の是非を判断し、安全に改善する責任を持つ開発者・アーキテクト・運用担当・プロダクト責任者。
- **約束している体験:** UX-1 判断を起点にする / UX-2 各状態の主操作は 1 つ / UX-3 段階的に詳しくする / UX-4 根拠と不確実性へ戻れる / UX-5 AI の提案と人の確定を分ける / UX-6 文脈を保って共同検討する / UX-7 失敗しても再開できる。

## 範囲と方法

- **体制:** 主担当(Claude Fable 5.2)が方針・実画面確認・裏取り・統合を行い、委任先(Claude Opus 5.5)5 体が領域別に読み取り監査を行った。領域は「入口・導入」「理解フェーズ」「設計 lineage」「観測・評価ループ」「進化・AI アシスタント」。
- **実画面:** 空の一時 DB、`LLM_PROVIDER=mock`、reasoning モデル未設定で Control Server と Dashboard(Vite dev)を起動し、1280×720 で初回利用者の経路を操作した。経路は ログイン → Overview → Repository 登録 → Snapshot 作成 → Interview 開始 → System Understanding の Build → 各画面の空状態。対象リポジトリは `examples/simple-pipeline` を複製した検証用リポジトリ。
- **裏取り:** 委任先の指摘のうち 14 件は、主担当が該当コードを読んで確認した。
- **再掲の除外:** [2026-08-11 監査](end-to-end-ux-audit-2026-08-11.md)(#366 で修正)と [2026-09-26 監査](ux-audit-2026-09-26.md)(#466 で修正)の項目は再掲していない。修正後に崩れたものだけ、その旨を書いて挙げた。

- 利用者テスト、スクリーンリーダー実機、実 IME、モバイル幅は確認していない。
- 行番号は基準 commit のもの。
- コードは変更していない。

優先度は、P1=主要タスクを阻害する・誤操作を招く、P2=判断・発見性・継続を損なう、P3=効率の改善、とする。

## 判断が必要な点

- **C3 と C4 は仕様の判断を含む。** C3 は候補の最小件数、C4 は入力保存の既定値で、後者は秘密情報の扱い(Principle 9)と Principle 4 に関わる。
- **D1 は意図された設計の可能性がある。** 昇格を理解の確認後に限るかは、[System 正準 Understanding](../01-specifications/product/canonical-understanding.md) の所有者の判断である。
- **B3 と A6 は reasoning モデル未設定の環境で見た。** 実 LLM を設定した環境で同じ状態になるかは未確認。
- **C8 は未再現。** コード上の経路から推定した。

## 維持すべき点

- 状態・主操作・例外はサーバーが決め、画面は表示するだけ(WorkflowLocationCard、Overview の `next_action`)。
- 取得失敗・0 件・保留を区別している画面が多い(InterviewLoadErrorCard、`qaFetchStatus`、Requirement の対応表示)。
- Overview は取得できない・処理中の状態を、無効化したボタンではなく文章で示す。
- Snapshot preflight と Replay readiness が、生成の前に止める。
- publish の承認ダイアログは差分を表示し、差分を取得できなければ承認させない。
- 変更候補は prefill を先にし、「この時点では何も保存されていません」と明示する。
- SDK policy の `shadow` と実行モードの `shadow` を、注記付きで別の値として並べている。
- 判断の記録時に読み込んだ時点の内容と照合し、古ければ読み込み直しを案内する。

## 残る確認

- 実 LLM・実データでの Interview(W2〜W7)と、補足・昇格候補がある状態での作業面の位置。
- 同期実行の Replay / Experiment の所要時間と、proxy のタイムアウト。
- Blueprint の 9 列の表と Value Network の図の、390px 幅での可読性。
- Value Network の図(`role="img"` の内側のボタン)の読み上げ環境での操作可否。
- 代表利用者による評価(#463)。初見の利用者が Interview と System Understanding を区別できるかを含む。

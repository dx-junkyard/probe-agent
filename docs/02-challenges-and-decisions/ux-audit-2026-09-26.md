## 結論

優先すべきは、操作対象の取り違えを防ぐこと、入力を失わないこと、通信失敗を正しく伝えること。その上で、機能名を探すナビゲーションから「今の目的と次の操作」が分かる導線へ整理する。

今回の改善バックログは20件（P1: 2件、P2: 16件、P3: 2件）。実画面で確認した事象、コードから確認した分岐、設計改善の提案を区別した。ユーザーテストによる頻度・所要時間の測定はしていない。

## 範囲と方法

- チーム：主担当が横断レビュー・実画面確認・統合。3名のAgentが「情報設計／導入」「業務フロー」「共通UI／アクセシビリティ／アシスタント」を並行監査。
- コード：Dashboardのルート・共通UI・認証・主要ページと関連仕様。参照行は現在の作業ツリー基準。既存の未コミット変更も含めた現状を評価した。
- 実画面：`http://localhost:8501/`。初回はログイン画面、その後ログイン済み画面を確認。Overview入口、Journey Service Blueprint、Connect SDK、System作成ダイアログ、存在しないURLを確認。390×844pxでヘッダーを確認し、表示幅は復元した。
- 制約：稼働ビルドと作業ツリーの完全一致は未検証。保存、失効、実験実行、AIへの質問送信は実行していない。コード上の発生条件を、すべて実環境で再現したという意味ではない。
- テスト：既存のlayout-navigation／phase0-empty-states／tabs／assistant-discussion-threadの4ファイルを実行しようとしたが、`@rolldown/binding-darwin-arm64` 不足によりVitest起動前に停止。Viteの起動も同じ理由で失敗。テストの合否は未判定。依存関係やlockfileは変更していない。
- 過去監査：2026-08-11の指摘をそのまま再掲せず、現行コードで確認。鮮度表示、token状態、モバイルナビ、Tabs操作などの既存改善を考慮した。

優先度は、P1＝誤操作・主要操作へのアクセスを阻害するため先に修正、P2＝作業継続・判断・発見性を損なう、P3＝入力効率・継続利用の改善、とする。

## 改善バックログ

### UX-01 / P1 — API tokenの対象Systemを見分けられない

**根拠：コード＋実画面の表構成確認。** `/tokens/me` は利用者の全tokenを返すが、Connect SDKはSystemで絞らず、一覧にも失効確認にも対象Systemを表示しない。「発行先のSystem」は表示されるため、一覧も同じ対象だと誤解しやすい。別Systemの同名tokenを誤って失効させる可能性がある。実際の誤失効は行っていない。

**改善・受入条件：** 選択Systemで初期絞り込み。「全System」は明示的に切り替える。System列と確認文に対象名を表示し、同名tokenでも対象を識別できる。System未関連のtokenも専用表示する。

根拠：`apps/dashboard/src/pages/connect-sdk.tsx:64,115,252,297`、`apps/control-server/app/routes/auth.py:415`。

### UX-02 / P1 — 共通ダイアログをキーボード・読み上げで扱えない

**根拠：コード＋実画面。** 共通Dialogにdialogロール、タイトル参照、初期フォーカス、フォーカストラップ、Escape、フォーカス復帰がない。System作成画面でEscapeを押しても閉じず、開いた後のフォーカスがbodyにあること、dialogロールが0件であることを確認した。承認・失効などの重要操作にも同じ部品が使われる。

**改善・受入条件：** 既存の`useModalSurface`と共通化。開くと内部へフォーカスが移り、Tabが内部を循環し、Escapeで閉じ、起点へ戻る。読み上げでタイトル・対象・操作が理解できる。

根拠：`apps/dashboard/src/components/ui/dialog.tsx:21`、再利用候補：`apps/dashboard/src/lib/modal-surface.ts`。

### UX-03 / P2 — 画面確認のための操作で未保存入力が消える

**根拠：コード。** Experiment作成はダイアログを閉じると無条件にresetする。背景クリックでも閉じる。Repository設定はタブ切替でフォームがアンマウントされ、編集内容が失われる。長いpatchやパターン設定をやり直すことになる。

**改善・受入条件：** 閉じる／タブ移動と破棄を分離し、下書きを保持する。Experimentの背景クリック、Repositoryのタブ往復、System切替、画面離脱で未保存内容を無警告に失わない。保存中も処理結果と下書きの所属が明確である。

根拠：`apps/dashboard/src/pages/experiments.tsx:181,304`、`apps/dashboard/src/pages/repository.tsx:130,748`、`apps/dashboard/src/components/ui/tabs.tsx:131`。

### UX-04 / P2 — 入力途中の実験候補が成功時に黙って除外される

**根拠：コード。** 完全入力の候補が2件あれば、3件目のラベル・risk noteなどが入力されていてもpatchが空ならfilterで除外して送信する。成功した実験が利用者の意図した比較対象と異なる。

**改善・受入条件：** 完全な空行と部分入力を分ける。部分入力には「候補3のpatchが必要」などの行別エラーを表示し、修正または明示削除まで送信しない。

根拠：`apps/dashboard/src/pages/experiments.tsx:188`。

### UX-05 / P2 — 通信失敗が「未作成」や「読み込み中」になる

**根拠：コード。** Probe Plannerは初回一覧取得失敗を空一覧と同じ扱いにする。Journey Blueprint差分はデータがない状態をすべて読み込み中と表示する。Generation履歴にも失敗と0件の混同がある。利用者は再作成すべきか、待つべきか判断できない。

**改善・受入条件：** 読み込み中／取得成功0件／失敗／利用不可を分離し、失敗時は再試行を主操作にする。500・オフライン・権限エラーで「まだありません」を出さず、取得失敗から対象不存在を判定しない。

根拠：`apps/dashboard/src/pages/probe-planner.tsx:40,95,187`、`apps/dashboard/src/pages/journey-blueprint.tsx:185`、`apps/dashboard/src/components/journey-blueprint/diff-panel.tsx:11`、`apps/dashboard/src/pages/generation.tsx:28,114`。

### UX-06 / P2 — 認証・System取得の失敗から再開しづらい

**根拠：コード。** 初期認証は順番に取得完了を待ち、通常JSONリクエストにアプリ側タイムアウトがない。`/systems`失敗は握りつぶされ、初回は空配列のまま「System未作成」へつながり得る。利用中の401をAuth状態と連携して再ログインへ導く共通処理もない。実画面では読み込み表示が継続した後に表示されたが、その遅延原因は特定していない。

**改善・受入条件：** 認証失効、サーバー到達不能、System取得失敗を別状態にする。適切な待ち時間後に説明と再試行を表示。401は入力を保全して再認証し、復帰できる。成功した0件だけを「未作成」とする。

根拠：`apps/dashboard/src/api/auth.tsx:27,36,47`、`apps/dashboard/src/api/client.ts:94`、`apps/dashboard/src/components/layout/app-layout.tsx:41`。

### UX-07 / P2 — 履歴読込前に送った会話が表示から消え得る

**根拠：コード上の競合条件。実環境での遅延再現は未実施。** 永続スレッド未解決の間は一時会話へ送信できるが、解決後は表示元が永続履歴へ切り替わる。一時会話との移行処理がないため、取得完了前に送った質問・回答が表示から外れ得る。

**改善・受入条件：** 履歴初期解決中は状態を示して送信を待機させるか、送信内容を確実に引き継ぐ。取得失敗時は保存されない会話であることを明示。履歴応答を遅らせても質問が消えず、二重送信も起きない。

根拠：`apps/dashboard/src/components/assistant-panel.tsx:498,508,586`。

### UX-08 / P2 — tokenのコピー失敗でも成功と伝える

**根拠：コード。** Clipboard APIの完了を待たず成功toastを出す。一度だけ表示されるtokenなので、コピーしたつもりで離脱すると再発行が必要になる。

**改善・受入条件：** `writeText`成功後だけ通知する。拒否時はエラーと手動コピー導線を表示し、tokenを保持。コピー拒否条件のテストで成功表示を出さない。

根拠：`apps/dashboard/src/pages/connect-sdk.tsx:165,175`。

### UX-09 / P2 — ログインを挟むと共有リンクの目的地を失う

**根拠：コード。** 未認証時に元URLを保持せずloginへ送り、ログイン後は常にOverviewへ戻す。対象付きリンクから入っても探し直すことになる。

**改善・受入条件：** アプリ内のpathname・query・hashを保持して復帰。対象付きURL→ログイン→同じ対象の画面、が成立する。

根拠：`apps/dashboard/src/components/layout/app-layout.tsx:53`、`apps/dashboard/src/pages/login.tsx:35`。

### UX-10 / P2 — Decision Workspaceの選択とURLが同期しない

**根拠：コード。** `?open=`はstate初期値としてのみ読み、選択・作成時にはURLを更新しない。共有・再読込・ブラウザー履歴で対象が維持されない。

**改善・受入条件：** 選択IDをURLと同期し、再読込・戻る／進む・URL共有で同じWorkspaceを開く。無効IDも一覧へ戻れる。

根拠：`apps/dashboard/src/pages/workspaces.tsx:34,55,61`。

### UX-11 / P2 — Setup Guideの「次の操作」が操作先につながらない

**根拠：コード。** 状態別の次の操作は文字列のみ。冒頭のtoken発行リンクは存在するが、状態に応じた設定箇所・Trace確認・復旧確認へは直接進めない。

**改善・受入条件：** 状態に応じて「tokenを発行」「設定例を開く」「Traceを確認」などのCTAを一つ表示する。案内を読んでからメニューを探し直さず目的の操作へ到達できる。

根拠：`apps/dashboard/src/pages/setup-guide.tsx:159`、`apps/dashboard/src/components/setup-next-step.ts:34`。

### UX-12 / P2 — Journeyを選べない状態でも「選択してください」と案内する

**根拠：コード＋実画面。** Journey Service Blueprintで選択肢が「未選択」のみなのに、本文は「Journeyを選択してください」。コードは取得中・失敗・0件を分離せず、作成先へのCTAもない。実環境の選択肢不足の原因が真の0件か取得状態かは未特定。

**改善・受入条件：** 真の0件ならUX Design StudioのJourney作成へ誘導。取得失敗なら再試行。選択不能な操作を主案内にしない。

根拠：`apps/dashboard/src/pages/journey-blueprint.tsx:122,151`。

### UX-13 / P2 — ナビゲーションの情報量と薄い表示が発見性を下げる

**根拠：コード＋実画面。影響の程度は設計評価。** UnderstandとObserve & Evaluateには各10項目があり、全グループを常時表示。補足文は狭いサイドバーで省略される。将来フェーズはグループ全体が半透明だがリンクは操作可能で、無効項目のように見える。Map／Lineage／Blueprintを使い分ける学習負担が大きい。

**改善・受入条件：** 目的別の主要入口と詳細ビューを段階化し、グループ展開・画面検索を提供。現在地はバッジで示し、利用可能なリンクの文字は薄くしない。初見利用者が「現状理解」「要件設計」「比較評価」の開始地点を選べるか検証する。具体的コントラスト比は別途実測する。

根拠：`apps/dashboard/src/components/layout/sidebar.tsx:60,105,246,314,390`。

### UX-14 / P2 — 390px幅でヘッダーの操作とSystem名が重なる

**根拠：実画面＋コード。** Journey Service Blueprintを390×844pxで表示すると、System選択欄付近に右側の通知・操作アイコンが重なった。単に画面幅に収まっているかだけでは、この衝突を見逃す。

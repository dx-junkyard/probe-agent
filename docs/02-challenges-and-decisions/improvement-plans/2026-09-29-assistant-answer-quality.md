# IP-20260929-01: AIアシスタントの回答品質と応答時間を改善する（Epic #467）

**役割:** decision-or-gap-record。**日付:** 2026-09-29。**状態:** 実装済み（構造検証まで）。実LLM評価・代表利用者評価は未実施。提示記録: [G-20260929-01](../../../improvement/records/2026-09-29-assistant-answer-quality-guidance.md)。
**基準版:** `50bdd05`（origin/main。Issue本文の調査版 `d821a54` を含む）。**依頼:** Epic #467 と子Issue #468〜#473 の実装。
**担当:** コーディングエージェント（統括1、実装サブエージェント複数）。有料API・本番変更・外部送信は範囲外。

## 状況・目的

利用者報告「回答品質が低い」「応答が遅い」。実際に問題となった会話・稼働モデル・実入力token・実測レイテンシは未取得。
基準版のコード観測（Issue #467 の調査根拠）を状況の入力とし、各要因の寄与率は未確定のまま扱う。
目的は、①同じ固定課題で品質と時間を比較できる計測基盤、②確実に無駄な処理（診断の重複）の削減、
③必要な根拠の選択と不足・省略の明示、④根拠のない断定を事実として見せない回答契約、
⑤失敗を正常回答に見せない応答、⑥待ち時間短縮の候補を実測で採否できる設定点、を用意すること。

正本契約: [assistant-answer-quality.md](../../01-specifications/capabilities/assistant-answer-quality.md)。

## 観点の選択（手動照合、`probe-agent-ec/0.2`）

| 観点・事例 | 照合 | 利用 |
| --- | --- | --- |
| EC-P06 利用成立（IK-0004） | 適合。構造テスト成功を回答品質の実測と見なす危険が本Epicの中心 | 構造検証（偽LLM）と実LLM品質評価と代表利用者評価（#463）を3つに分けて記録する |
| EC-P04 正本・派生物の鮮度 | 適合（限定）。claimsや過去回答の本文を版なしで再利用しない | 通常askへはbundleの事実を版・digest付きで接続し、claims本文は再利用しない |
| EC-P02 対象・依存版 | 適合（限定）。LLM後の対象再解決・保存時再検証を省略しない | 診断共有はリクエスト内に限り、永続キャッシュを導入しない |
| EC-P05 評価・反復・共有予算 | 要観測。採否基準を候補比較の前に固定する | 閾値を検証文書へ先に書き、実LLM評価前に緩めない |
| EC-LP-0001 / EC-LP-0002（ローカル候補、未コミット） | 参照候補のみ。当該不具合の発生も候補の効果も認定しない | リクエスト内共有へ永続版管理を過剰適用しない判断にだけ使う |

## 候補と判断

| 候補 | 判断・理由 |
| --- | --- |
| 計測・固定課題・診断共有・構造的な情報選択・根拠/失敗契約 | 採用。モデルに依存せず品質と時間を同じ課題で比較できる |
| 専用モデル設定・出力量調整・段階表示 | 条件付き。設定点だけ用意し、既定値は変更前と同一。実測比較後に採否 |
| 強いモデルへの一律変更、全情報の常時投入、会話要約の永続キャッシュ、無制限の自律調査 | 見送り。品質改善の根拠がなく遅延・費用・古い前提の混入を増やし得る |
| 自由文からの意図分類器（キーワード） | 見送り。Principle 6 に反し、誤分類で必要情報を落とす。選択は構造的事実だけで行う |
| 毎回別LLMによる根拠検証 | 見送り。呼出し回数と時間を倍にする。意味的裏付けは固定課題と人間評価で見る |

- 子Issueごとの受入条件はIssue本文のとおり。採否の数値基準は
